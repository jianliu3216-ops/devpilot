# Autopilot 智能流水线 - 状态（CICD 别名）

**作用：** 每次新开 Claude Code 会话后，调用这个 Skill 自动读取流程文档，恢复工作状态。

> 本 Skill 与 `/project-autopilot-status` 功能完全相同，保留此别名供老用户使用。

## 执行步骤：

1. **读取 README.md**：读取当前 Autopilot 框架目录下的 `README.md`，理解整个 Autopilot 智能流水线的流程规则
2. **读取 CLAUDE.md**：读取当前 Autopilot 框架目录下的 `CLAUDE.md`，获取行为规则
3. **检查是否已有目标项目路径**：
   - 如果用户还没有提供目标项目路径 → 先询问用户
   - 如果用户已经提供目标项目路径 → 扫描目标项目，检查已有产出文档，总结各阶段完成状态
4. **总结当前状态**：框架目录 + 目标项目各需求状态
5. **提示下一步**：给出触发方式示例（关键字 / Skill命令 / 传统编号三种方式）

## 状态检查规则

扫描目标项目 `docs/` 目录时，按以下逻辑判断：

| 状态 | 含义 | 判断条件 |
|------|------|----------|
| ⏳ 待开始 | 需求目录已创建但无文档 | 目录存在，内部无阶段文档 |
| 🔄 进行中 | 某个阶段正在执行 | 部分阶段文档存在，未全部完成 |
| ✅ 已完成 | 所有阶段文档齐全 | 01~05 全部存在 |
| 🔁 变更中 | 需求变更流程正在执行 | CHANGELOG.md 中有未关闭的变更记录 |

## 状态输出格式：

```
📊 项目状态总览

项目路径：D:\projects\my-app

需求列表：
  ✅ user-login（用户登录注册）    — 全部阶段已完成
  🔁 message-push（消息推送）     — 变更中
  ⏳ order-export（订单导出）     — 待开始

知识库：✅ 已生成（2026-04-20）

下一步建议：
  - message-push：继续重做 03-software-design
  - order-export：输入"需求分析：订单导出功能"开始
```

## 牢记规则：

- 所有生成的文档和代码都必须输出到目标项目目录，不能输出到框架目录
- 每个需求的文档输出到 `docs/{需求标识}/` 目录下
- 知识库保持共享（整个项目一份），变更时增量更新
- 每个阶段完成后，必须停下来等待用户确认
- 流程最后一步（测试报告完成）必须执行知识库增量更新
- 需求变更时 AI 自动分析影响范围，增量重做
