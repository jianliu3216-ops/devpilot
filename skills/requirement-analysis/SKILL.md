# 需求分析（Autopilot 任务3）

**作用**：将用户简单几句话的自然语言需求，整理成结构化的需求分析文档，自动评估变更级别。

## 前置条件

- 用户必须提供：目标项目路径 + 原始需求描述
- 可选：如果已生成知识库，自动带上作为参考

## 执行步骤

1. **读取 README.md**：读取 Autopilot 框架目录的 `README.md` 获取完整流程规则
2. **确认目标项目路径**：如果用户在本会话中未明确提供，先询问（⚠️ auto-memory 或历史会话中的项目路径不算）
3. **自动建议英文需求标识**（kebab-case）：
   ```
   需求【{中文需求}】英文标识建议：{requirement-id}
   是否需要调整？
   ```
   用户确认后才继续
4. **自动评估变更级别（S/M/L）**：
   ```
   📊 变更级别评估
   需求类型：功能新增 / 框架升级 / ...
   预计影响文件数：约 XX 个
   变更级别：S / M / L
   判定依据：...
   后续流程：标准流程 / 轻量流程
   是否调整？（直接回车确认，或输入 S/M/L）
   ```
5. **输出文件**：`[目标项目]/docs/{需求标识}/01-requirements-analysis.md`
   - 项目背景、建设目标、功能需求列表、非功能需求
   - 待澄清疑问项（AI 主动列出）
   - 知识库锚点（如知识库存在）

## 变更级别判定规则

| 级别 | 条件 | 流程 |
|------|------|------|
| S | ≤3 文件 | 简要分析 → 跳过PRD/设计/测试用例 |
| M | 4-15 文件 | 完整6阶段标准流程 |
| L | >15 文件或跨模块 | 策略文档 → 分批执行 → 回归验证 |

## 用户输入示例

```
需求分析：我要做用户登录注册模块，支持手机号验证码登录和密码登录，记住密码。目标项目：D:\projects\my-app
```

```
需求分析：Spring Boot 从 2.7 升级到 3.2，目标项目：D:\projects\my-app
```
