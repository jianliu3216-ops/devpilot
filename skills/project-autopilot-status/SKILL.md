# Autopilot 智能流水线 - 状态

**作用：** 每次新开 Claude Code 会话后，调用这个 Skill 自动读取流程文档，恢复工作状态。

## 执行步骤：

1. **读取 README.md**：读取当前 Autopilot 框架目录下的 `README.md`，理解整个 Autopilot 智能流水线的流程规则
2. **读取 CLAUDE.md**：读取当前 Autopilot 框架目录下的 `CLAUDE.md`，获取行为规则
3. **检查是否已有目标项目路径**：
   - 如果用户还**没有提供**目标项目路径 → 先询问用户，请用户提供目标项目路径
   - 如果用户**已经提供**目标项目路径 → 扫描目标项目，检查已有产出文档，总结各阶段已完成状态和进度
4. **总结当前状态**：
   - 框架目录：共用框架环境已就绪
   - 目标项目：列出哪些需求已启动，每个需求各阶段完成状态
5. **提示用户输入开始任务**：给出输入格式示例，提示用户开始下一阶段

## 需求标识规则（多需求区分）

每个需求必须有一个**英文短标识**（kebab-case），用于创建独立的文档目录。

### 新需求启动流程：

1. 用户输入需求描述（中文即可）
2. AI 自动生成英文标识建议
3. **必须提示用户确认**：
   ```
   需求【用户登录注册模块】英文标识建议：user-login
   是否需要调整？（确认后将以 docs/user-login/ 作为文档目录）
   ```
4. 用户确认或调整后，以该标识创建目录

### 目标项目目录结构（按需求隔离）：

```
目标项目/
├── docs/
│   ├── knowledge-base/                    # 共享，整个项目一份，增量更新
│   │   └── PROJECT_KNOWLEDGE_BASE.md
│   │
│   ├── user-login/                        # 需求A：全部阶段文档在一起
│   │   ├── 01-requirements-analysis.md
│   │   ├── 02-prd.md
│   │   ├── 03-software-design.md
│   │   ├── 04-test-cases.md
│   │   ├── 05-test-report.md
│   │   └── CHANGELOG.md                  # 该需求的变更记录
│   │
│   └── message-push/                      # 需求B：全部阶段文档在一起
│       ├── 01-requirements-analysis.md
│       ├── 02-prd.md
│       ├── 03-software-design.md
│       ├── 04-test-cases.md
│       ├── 05-test-report.md
│       └── CHANGELOG.md
```

### 用户输入格式：

```
开始任务3，目标项目：D:\projects\my-app，需求：做一个用户登录注册模块
```
AI 收到后自动提示英文标识确认，不需要用户自己想英文名。

## 状态检查规则（支持需求变更识别）

扫描目标项目 `docs/` 目录时，按以下逻辑判断每个需求的状态：

### 状态定义：

| 状态 | 含义 | 判断条件 |
|------|------|----------|
| ⏳ 待开始 | 需求目录已创建但无文档 | 目录存在，内部无阶段文档 |
| 🔄 进行中 | 某个阶段正在执行 | 部分阶段文档存在，未全部完成 |
| ✅ 已完成 | 所有阶段文档齐全 | 01~05 全部存在 |
| 🔁 变更中 | 需求变更流程正在执行 | CHANGELOG.md 中有未关闭的变更记录 |
| ✅✅ 变更完成 | 变更流程已走完 | CHANGELOG.md 中最新变更记录状态为"已完成" |

### 变更场景状态检测：

检查每个需求目录下的 `CHANGELOG.md`，如果存在则解析变更记录：

```
## 变更记录

### 变更1：增加 OAuth 第三方登录
- 状态：🔄 变更中          ← 检测到"变更中"，该需求状态显示 🔁 变更中
- 日期：2026-04-28
- 影响阶段：02-prd, 03-software-design
- 已重做：02-prd ✅
- 待重做：03-software-design ⏳

### 变更2：增加验证码功能
- 状态：✅ 已完成          ← 已关闭，不影响当前状态
- 日期：2026-04-25
- ...
```

### 状态输出格式：

```
📊 项目状态总览

项目路径：D:\projects\my-app

需求列表：
  ✅ user-login（用户登录注册）    — 全部阶段已完成
       最后变更：2026-04-25 验证码功能（已完成）
  🔁 message-push（消息推送）     — 变更中
       当前变更：增加邮件通知，影响 02-prd/03-software-design
       已重做：02-prd ✅
       待重做：03-software-design ⏳
  ⏳ order-export（订单导出）     — 待开始

知识库：✅ 已生成（2026-04-20）

下一步建议：
  - message-push：继续重做 03-software-design
  - order-export：开始任务3
```

## 牢记规则：

- 所有生成的文档和代码都必须**输出到目标项目目录**，不能输出到当前框架目录
- 每个需求的文档输出到 `docs/{需求标识}/` 目录下，不同需求完全隔离
- knowledge-base 保持共享（整个项目一份），变更时增量更新
- 每次调用 `/van` 时，必须拼上所有依赖文件的**完整绝对路径**
- 如果任务 2（私域知识库）已完成，必须在调用命令中添加指令：
  ```
  请参考 PROJECT_KNOWLEDGE_BASE.md 理解项目，不需要读取整个项目代码
  ```
- 每个阶段完成后，必须停下来等待用户确认，不能自动进入下一阶段
- 严格遵循顺序：任务 1 → 任务 2 → 任务 3 → 任务 4 → 任务 5 → 任务 6 → 任务 7 → 任务 8 → 任务8.5（知识库增量更新）
- **不管哪种场景**，只要流程走到最后一步（测试报告完成），**必须**执行知识库增量更新（任务8.5）
- 知识库增量更新：只更新本次变更涉及的章节，不需要全量重扫，追加更新记录
- 需求变更时使用任务9，AI自动分析影响范围，增量重做，不需要从头走全量流程

## 支持的场景：

### 场景1：正常需求实现
- 任务2（首次全量知识库）→ 任务3 → 任务4 → 任务5 → 任务6 → 任务7 → 任务8 → 任务8.5（知识库增量更新）
- 用户输入示例：
  ```
  开始任务3，目标项目路径：D:\projects\my-app，需求：我要做一个用户登录注册模块
  ```
  AI 自动提示：
  ```
  需求【用户登录注册模块】英文标识建议：user-login
  是否需要调整？（确认后将以 docs/user-login/ 作为文档目录）
  ```

### 场景2：需求变更
- 任务9：9.1描述变更 → 9.2 AI影响分析 → 9.3确认范围 → 9.4增量重做 → ... → 测试报告 → 任务8.5（知识库增量更新）
- 用户输入示例：
  ```
  执行任务9，需求标识：user-login，需求变更：登录页面增加忘记密码链接
  ```
  ```
  执行任务9，需求标识：message-push，需求变更：新增邮件通知支持
  ```

## 输出要求：

### 情况 1：用户未提供目标项目路径
- 告知已读取框架文档，流程规则已理解
- 说明需要用户提供目标项目路径才能继续
- 给出目标项目路径输入示例

### 情况 2：用户已提供目标项目路径
- 告知已读取框架文档，流程规则已理解
- 汇总当前目标项目各需求状态（包含变更中状态识别）
- 格式见上方"状态输出格式"
- **额外检查**：如果所有需求所有阶段已完成，检查知识库是否有更新记录（任务8.5是否执行过）
- 提示用户输入开始下一阶段任务，给出输入格式示例
- 如果项目已完成所有阶段，提示用户可以进行需求变更：
  ```
  执行任务9，需求标识：xxx，需求变更：你的变更描述
  ```
