把「少注入」从散落规则变成三条默认强制法律，解决小问题走完整仪式、token 膨胀、复读前序文档三大痛点。

## 3. 功能规格

### FR1 注入法律一（知识库注入形态）

任何阶段引用知识库路径/符号/模块作为「当前事实」前：必须已运行 `verify-kb-facts.js --query "<任务关键词>"`，且只引用 `PROJECT_KNOWLEDGE_ADMITTED.md` / `docs/knowledge-base/.verified/query-admit.md` 中 **pass** 断言。**禁止**把 BASE/DETAIL 全文或大段内容贴进上下文；BASE/DETAIL 仅作检索线索。适用任务：3、4、5、6、9（扩展自原任务3 专属）。

### FR2 注入法律二（阶段推进压缩）

进入新阶段前 MUST 运行 `compress-handoff.js`（源文档未变自动复用旧包），只读 `.handoff/*.context.md` + 按「按需下钻建议」打开章节；**禁止**全文复读前序阶段文档（01/02/03/04/05）。

### FR3 注入法律三（S 级纪律）

S 级确认后：跳过 PRD（02）、设计（03）、测试用例（04）文档；代码实现后仅出**简要测试报告**（05 简化版：改动点、验证命令与结果、风险）+ 知识库增量。**模型不得以「质量」为由自行升级级别**；升级只能由后续阶段发现影响扩大时提示用户确认（沿用「只升不降」规则）。

### FR4 门控触发范围扩展

`cicd-rules.md` §4 从「任务3 事实门控 MUST」扩展为「任务 3/4/5/6/9 在把知识库当事实前 MUST 带 --query 跑门控」；fact-gate SKILL 触发节同步。

## 4. 非功能需求
