# DevPilot 定制与拓展指南

DevPilot 设计为开放式框架，任何人都可以在此之上定制自己的开发流水线。

---

## 场景1：我想为 XX 产品增加专属特性

典型需求：某个项目有自己的编码规范、技术栈约束、固定模板，希望在流水线中强制执行。

### 需要修改的文件（从简到深）

| 改什么 | 文件 | 作用 |
|--------|------|------|
| 增加触发关键字 | `CLAUDE.md`（触发规则表） | 新增自然语言关键字 → Skill 映射 |
| 增加新 Skill | `skills/你的skill名/SKILL.md` | 新增一个流水线命令（安装后自动注册） |
| 增加流程规则 | `.claude-collective/cicd-rules.md` | SessionStart 自动注入的规则（所有会话生效） |
| 增加专属 Agent | `.claude/agents/你的agent名.md` | 定义专业 Agent 的角色和能力 |
| 增加 Hook 行为 | `.claude/hooks/` + `.claude/settings.json` | 在工具调用前后注入自定义行为 |
| 修改流水线行为 | `README.md`（AI 规则书） | 调整流程阶段、输出要求、质量标准 |

### 最简示例：新增"生成API文档"Skill

```bash
# 1. 创建 Skill 目录和文件
mkdir -p skills/api-doc-generator
cat > skills/api-doc-generator/SKILL.md << 'EOF'
---
name: api-doc-generator
description: 扫描目标项目代码，自动生成 API 接口文档
---

# API 文档生成器

## 执行步骤
1. 扫描目标项目路由文件
2. 提取接口定义（路径、方法、参数、返回值）
3. 生成 Markdown 格式的 API 文档
4. 输出到 `{目标项目}/docs/api-doc.md`

## 输入格式
  生成API文档，目标项目：D:\my-project
EOF

# 2. 在 CLAUDE.md 触发规则表中增加一行
# | `生成API文档`、`API文档` | api-doc-generator | ...
```

## 场景2：我想完善这个工程

### 推荐入手路径（按难度递增）

| 阶段 | 做什么 | 涉及 |
|------|--------|------|
| **Level 1：用起来** | 在真实项目中完整走一遍流程，记录体验问题 | 无需改代码 |
| **Level 2：改文档** | 修正 README/CLAUDE.md/快速入门 中的不准确描述 | 编辑 `.md` 文件 |
| **Level 3：改 Skill** | 优化某个 Skill 的提示词，让 AI 表现更好 | `skills/*/SKILL.md` |
| **Level 4：改规则** | 调整流程触发规则、变更分级判定逻辑 | `CLAUDE.md`、`cicd-rules.md` |
| **Level 5：改 Hook** | 修改 SessionStart 注入逻辑、增加新钩子 | `.claude/hooks/*.sh` + `settings.json` |
| **Level 6：改 Agent** | 优化 Agent 定义、调整角色提示词 | `.claude/agents/*.md` |
| **Level 7：改安装器** | 优化 install.sh 依赖检测、跨平台兼容 | `install.sh` |

### 关键入口文件速查

```
想改流程规则      → README.md（AI 完整规则书）
想改触发关键字    → CLAUDE.md（触发规则表）
想改Session规则   → .claude-collective/cicd-rules.md
想改Skill行为     → skills/<skill名>/SKILL.md
想改Agent行为     → .claude/agents/<agent名>.md
想改Hook行为      → .claude/hooks/<hook名>.sh
想改安装过程      → install.sh
想改知识库规则    → docs/KNOWLEDGE_BASE_RULES.md
```
