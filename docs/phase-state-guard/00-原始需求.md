# 00 原始需求：阶段状态与证据守卫（phase-state-guard）

- 需求标识：`phase-state-guard`
- 中文名：阶段状态与证据守卫（机器状态 + 硬门禁 + 可恢复）
- 所属版本规划：`docs/DEVPILOT_VERSION_PLAN.md` **2.5.0**（L 级）
- 创建时间：2026-09-30
- 原始诉求（用户场景归纳）：

> 阶段推进靠模型自觉：Agent 口述 done 就能跳阶段；测试报告没写也可能去做知识库更新；会话中断后要靠重读文档猜进度。
> 借鉴 Comet 的机器状态 + guard + resume（规划 §1.2 三样），但保留人工确认门控，不引入自动推进。

## 需求描述

为每个需求引入机器可读状态与脚本守卫：

1. `docs/{需求标识}/state.yaml`：阶段、级别、状态、证据文件路径（规划 §6.2 字段锁定）
2. `devpilot-guard.js`：阶段守卫脚本——校验退出/进入条件（证据文件存在性），`--apply` 校验通过后更新 phase；每次迁移追加 `state-events.jsonl`（append-only 审计）
3. 可恢复：中断后读 `state.yaml` + `.handoff` 压缩包即可续跑，禁止全量重读 00–05
4. 阶段枚举对齐现有流水线：`identified → original_req → analysis → (prd) → (design) → impl → (test_cases) → report → kb_update → done`；S 级括号内阶段标 `skipped: true`
5. Guard 替代不了人工确认：`waiting_confirm` 时不允许 `--apply`

## 非目标（本版本禁止）

- 不做 Comet 级 Verifier 双 Agent（后续可选，非必做）
- 不做 Dashboard / Web 界面
- 不新增对外斜杠命令（脚本由流水线内部 node 调用）
- 不改事实门控与压缩脚本（2.4 已定型）
- 不做知识库形态改造（2.6.0）
