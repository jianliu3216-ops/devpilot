### 3.3 三层兜底路由 R4（含自定义描述循环）

解决「句子没命中任何关键字」时的行为。**三层，不二选一：**

| 层 | 条件 | 行为 |
|----|------|------|
| T1 意图明确 | 句子含任务关键字，或语义清楚对应某任务（如「帮我把这个 bug 修了」→ 需求） | 直接进对应任务，不问 |
| T2 模糊但动作轻 | 无关键字、语义偏查询/只读（查状态、看文件、解释代码） | 直接干，边干边说明；不开流水线 |
| T3 模糊且动作重 | 无关键字，语义可能触发写操作/流水线/改代码（含完全无法判断） | 停：输出兜底菜单 + 默认猜测，等用户选择 |

T3 兜底菜单格式（一次问完，带默认建议，不学 Superpowers 连环追问）：

```
我没法确定你想做哪件事。你可以：

1. 需求：<一句话描述>        ← 改代码/新功能从这里进
2. 生成知识库                 ← 让 AI 理解现有项目
3. 查看状态                   ← 看各需求进度
4. 需求变更：<标识> <描述>    ← 改已有需求
5. 其他任务：直接说（生成PRD / 软件设计 / 代码实现 / 测试报告 / 更新知识库 …）

我的猜测：你大概想 <默认猜测>。回「1」或直接给一句话描述即可。
```

**自定义描述循环（用户已确认的追加契约）：**

```text
用户在菜单下输入自定义描述（不选 1–5，直接写一句话）
  → AI 对这句话再走一次 T1/T2/T3 判定
  → 能定位到任务（T1）或属轻动作（T2）→ 执行
  → 仍无法判断/定位（T3）→ 必须再问：给出 2 个以内最可能的候选 + 各自后果一句话，让用户二选一或改写
  → 二次仍无法判断 → 列精简任务清单请用户点名；禁止第三次猜测，禁止开工具
```

约束：
- 自定义描述循环**最多两轮**；两轮后仍未定位 = 必须点名选择，杜绝无限追问
- T2 判定错误（以为轻其实重）时的止损：执行前发现要写文件/改代码，立即停并转 T3
- 救援关键字：`菜单`（任何时候）→ 重新打印激活菜单，清除当前猜测状态
- R4 写入 CLAUDE.md 会话持久化规则；兜底菜单模板写在 init SKILL 第 2 步之后
